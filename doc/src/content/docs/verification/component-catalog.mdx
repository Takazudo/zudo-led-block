:::caution[カタログは製造の承認ではありません]
部品証跡カタログに 30 型番が載っていても、A5 は **製造リリースではありません**。制御基板は未配線で、実機の評価はまだ行っていません。
記録ページの配置とピンマップは A5 の **履歴上のネットリスト** から写したもので、現在の A6 の設計状態でも、実装後の確認でもありません。
:::

## 何を照合しているか

`scripts/a5_catalog.py reconcile` が、不変の A5 チェックポイントから次の 4 つを読み、`provenance/a5-catalog/reconciliation.json` を決定的に生成します。

| 入力 | 役割 |
|---|---|
| `engineering/a5/electronics/fitted_component_ledger.json` | 実装する型番と配置の台帳 |
| `engineering/a5/procurement_rows.json` | メーカー名・パッケージ・役割・JLC の注文コード |
| A5 の JLCPCB スナップショット (`ic_led_evidence/` などの `*.snapshot.json`) | 販売店の掲載内容 (型番・ブランド) |
| `engineering/a5/integration/native_schematic/*/netlist.xml` | 3 種類の基板の配置・ピン・ネット (KiCad 10.0.8 の書き出し、2026-11-06) |

入力ファイルはすべて SHA-256 と一緒に記録されます。照合の結果は次のとおりです。

| 数え方 | 値 |
|---|---|
| 実装する型番 (注文できる識別子) | **30** |
| 設計上のユニーク配置 | **71** (制御基板 59 + LED 基板 10 + 電源変換基板 2) |
| 1 台あたりの実装点数 | **81** (制御基板 59 + LED 基板 10 × 2 枚 + 電源変換基板 2) |

テストパッド TP1〜TP5 (注文できる識別子が無い)、外部ケーブルやパネルなどの外部品、履歴上の代替部品、不採用の候補は数えません。
実装部品は `WS2812B-2020-V6` と `TPS2552DBVR-1` で、代替の `WS2812B-MINI-V6` や `TPS2553DBVR-1` は実装部品として扱いません。

## 型番の表記の違い (C5665)

C5665 の電源ヘッダは、A5 の中で 2 通りに書かれています。

| 表記 | どこに書かれているか |
|---|---|
| `2.54-2*5P` | 実装台帳、電源変換基板のネットリスト、LCSC の製品ページ (2026-11-08 に取得) |
| `2.54-2*5P2.54 mm pitch 2×5 pin IDC box header` | 調達表、A5 の JLCPCB スナップショット |

JLCPCB の型番欄は、型番 `2.54-2*5P` の後に説明文を続けて表示しています。同じ注文コードとブランドで、LCSC は型番を `2.54-2*5P` だけで掲載しています。
そのため正準の型番を `2.54-2*5P` とし、両方の表記を確認済みの対応表 `provenance/a5-catalog/identity-crosswalk.json` に残しています。
照合は文字列の完全一致で行います。曖昧一致や文字の削除はしません。対応表に無い表記の違いは失敗になります。
このヘッダのメーカー一次資料は見つかっていないため、メーカー一次資料で確認した識別は **未解決** のままです。

## 出典の扱い

| 種類 | 扱い |
|---|---|
| メーカーのサイトから取得した PDF (`MANUFACTURER_PRIMARY`) | 取得したバイトの SHA-256、ページ番号 (0 始まりの物理ページと印刷ページ)、表・図・行の位置、短い抜粋を記録。この出典の事実だけが `PASS - primary-source confirmed` になれます |
| 販売店がホストするメーカー資料の写し (`MANUFACTURER_MIRROR`) | 権威が低いため、その事実は `UNSOURCED` のまま残します |
| 販売店の製品ページ (`DISTRIBUTOR_IDENTITY`) | 注文コードと型番の対応の確認だけに使います。性能の根拠にはしません |
| 取得できなかった資料 (`SOURCE UNAVAILABLE`) | ハッシュを 0 の番兵値にし、試した URL と理由を残します。依存する事実は `UNSOURCED` |
| A5 の記録 | A5 が記録した URL とハッシュは履歴として扱います。今日のバイトと同じかどうかを出典ごとに書いています |

A5 のスナップショットでは、スナップショット JSON 自体のハッシュ (確認したバイト) と、その中に記録された元の HTML のハッシュ (再確認していない) を分けて書いています。
価格と在庫は観測日付きの値で、見積りではありません。

## 確認していること

- `pnpm circuit:check`: 証跡バンドル・インベントリ・ルーティングがフレームワークの契約 (v1) を満たすこと。出力の `SCOPE:` 行のとおり、手動インベントリはネットリストとの結び付けを行いません。CAD が無効なので、ピンと資産の照合は `SKIP` です
- `python3 scripts/a5_catalog.py check`: インベントリの 30 行・71 配置、30 個の所有バンドル、販売店識別の事実、ピンマップ (A5 ネットリストのピン・名前・ネットとの完全一致)、公開する記録の選択が照合結果と一致すること。代替部品や重複・欠落が無いこと。後のリビジョン (例: A7) の行は、行 ID が `line-a7-`、所有バンドルが `component-a7-` で始まる場合に限り 30 型番の外に置けます。A5 の数え方には含めず、A5 の照合も緩めません
- `python3 -m unittest scripts/test_a5_catalog.py`: 欠落・重複・代替部品の混入・注文コードやメーカー名の不一致・LED 基板の倍数・C5665 の表記・ピンマップの改ざん・選択のずれ・後のリビジョンの行の命名違反を、それぞれ検出できること
- `pnpm test:browser`: カタログが 30 記録すべてにリンクし、各記録ページに識別・資料の判断・有効なページ内リンクがあること。BOM の各行が対応する記録ページへリンクすること

## 確認していないこと

- 配置・ピンマップが現在の設計や実装後の基板と一致すること (`NEEDS BENCH`)
- フットプリント・3D モデル・シンボルと資料の照合 (CAD は無効)
- フレームワーク `check-browser` の部品参照セクションと 3D ビューアの検査 (フットプリントが公開されないため実行されません)
- 部品の組み合わせでの電気的な余裕、起動・保護・温度・光学などの統合動作 (実機評価で確認します)
