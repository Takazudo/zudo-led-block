# リポジトリ面付け（オーナーが選んだ経路・製造リリースではない）

オーナーは 2026-11-12 に面付けの経路としてリポジトリ面付けを選びました（`engineering/a7/procurement/owner-decisions.json` の `panel-route`）。ここにあるのは生成器の基準セットで、**ここから直接アップロードしません。** 試験用試作ルートでアップロードする写しは日付付きの `../order/2026-11-13/`（Gerber zip・BOM・CPL・`SHA256SUMS`）で、その BOM / CPL はここのファイルとバイト単位で同じです。どちらも製造リリースではなく、readiness の発注ゲートは BLOCKED のままです。段階ごとの状態は `doc/src/content/docs/project/next-actions.mdx` を参照してください。

- `<board>-panel.json`（生成）: シート寸法、各基板の位置（凍結ファイルからの移動量）、切り溝、マウスバイトタブと穴、フィデューシャル、治具穴、DRC の例外。
- `<board>-panel_BOM_DRYRUN.csv` / `<board>-panel_CPL_DRYRUN.csv`（生成）: 単品の BOM / CPL を基板ごとに移動したもの。2 枚目以降の designator は `_2` などの接尾辞。CPL の原点はシートの左上の外形角（mm、Y は下向きが負）。
- `build-receipt.json`: 最後に全検査が通ったビルドのファイル名一覧。

| 基板 | シート | 載せる枚数 |
|---|---|---:|
| controller | 70 × 76.9 mm | 1 |
| led_leaf | 70 × 96.5 mm（捨て部分は FR-4 のまま） | 2 |
| power_adapter | 22.8 × 44 mm | 1 |

`python3 scripts/a7_panel.py` が生成し、`--check` が一致を確かめます（`a7_jlc_package.py` のあとに実行し、ページはそのあと `a7_jlc_package.py` をもう一度実行して更新）。`python3 scripts/a7_panel.py build --out <リポジトリ外の空ディレクトリ>` はピン留めの KiCad 10.0.8 イメージ（ネットワークなし、リポジトリは読み取り専用）で面付け基板を作って保存し、それを読み直して次を確かめてから Gerber・drill の zip を出します。CI の native ジョブで毎回実行します。

- 各基板の部品（属性・図形を含む）、パッド（各銅層の寸法・形・オフセット、穴、マスク/ペースト余白）、配線、ビア、ゾーン（外形と塗りつぶし形状）、図形・文字が、凍結した基板ファイルと移動量を除いて一致する。2 枚目以降は自分の接尾辞付きネットに載っていること。
- 面付けの Edge.Cuts から KiCad が求めた外形のうち、各基板の区画からタブを除いた部分が、凍結ファイルの外形と一致する（差の面積 0）。
- 穴（長穴を含む）が「凍結ファイルの穴を移動したもの＋マウスバイト穴＋治具穴」と一致する。
- マウスバイト穴・治具穴・フィデューシャルが計画どおりの位置・寸法・面にある。
- 面付け DRC の違反数が、種類ごとに元の基板の違反数 × 枚数と一致する。例外（`power_adapter` の `npth_inside_courtyard`）は件数を `build-receipt.json` に固定。
- CPL が KiCad 自身の位置出力と一致する（位置・回転・面）。

確かめていないこと: Gerber どうしの比較（面付けの Gerber は検査済みの面付け基板から出すだけ）、ネット名で決まるネットクラスや独自ルール（2 枚目以降のネット名が変わるので、そうした設定がある基板は `build` が止まる。今の 3 枚は Default のみ）。

規則は `../sources.json` の JLC のページ（2026-11-12）から: 5 mm のレール、2 mm の治具穴、1 mm のフィデューシャル（縁から 3.85 mm）、基板間隔 2 mm 以上、タブ幅 5 mm 以上、マウスバイト穴 0.5–0.8 mm・間隔 0.2–0.3 mm。次は提案値で、JLC の値ではありません: フィデューシャルのマスク開口 2 mm と横位置（シート幅の 30 %・70 %）、治具穴の位置、タブの位置と数、タブと部品の距離 1 mm、はみ出す部品への 1 mm の逃げ。タブの配置は機械的に未レビューです（controller は左辺の短い区間に 2 か所と右辺に 2 か所、led_leaf は向かい合う辺にタブがなく各 3 か所）。`power_adapter` は部品のコートヤードの外に 2 か所置けないため、タブを J1 の下に置いています。

マウスバイト穴は基板の縁の外に接して置くので、分割後は各タブの位置に最大約 0.3 mm の突起が残り、実物の外形は凍結ファイルの外形より少し出ます。凍結した基板ファイルは書きません。
